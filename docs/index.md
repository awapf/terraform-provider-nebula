# nebula Provider

Issues [Nebula](https://github.com/slackhq/nebula) certificates whose CA private key is a non-exportable Ed25519 key in the OpenBao or HashiCorp Vault transit secrets engine. The provider only ever reads the key's public half and asks transit to sign.

Certificates are built with Nebula's own `github.com/slackhq/nebula/cert` package. Every signature
transit returns is checked against the pinned key version's public key before use.

Only creating `nebula_ca` and `nebula_certificate` contacts OpenBao/Vault. Refresh, destroy,
`nebula_keypair` and `nebula_ca_bundle` work offline.

## Policy

The token needs no more than this (per CA key):

```hcl
path "transit/keys/nebula-ca" { capabilities = ["read"] }
path "transit/sign/nebula-ca" { capabilities = ["update"] }
```

## Example Usage

```terraform
terraform {
  required_providers {
    nebula = {
      source = "awapf/nebula"
    }
  }
}

# Address and token usually come from BAO_ADDR/BAO_TOKEN (or VAULT_ADDR/VAULT_TOKEN).
provider "nebula" {
  address       = "https://bao.example.com:8200"
  transit_mount = "transit"
}
```

## Schema

### Optional

- `address` (String) OpenBao/Vault address, e.g. `https://bao.example.com:8200`. Defaults to `BAO_ADDR`, then `VAULT_ADDR`.
- `ca_cert_file` (String) PEM file with the CA certificate(s) to verify the OpenBao/Vault TLS certificate. Defaults to `BAO_CACERT`, then `VAULT_CACERT`; otherwise the system trust store is used.
- `namespace` (String) Namespace to send requests to. Defaults to `BAO_NAMESPACE`, then `VAULT_NAMESPACE`.
- `skip_tls_verify` (Boolean) Disable TLS verification. Only for testing. Defaults to `BAO_SKIP_VERIFY`, then `VAULT_SKIP_VERIFY`.
- `token` (String, Sensitive) Token with `update` on `<transit_mount>/sign/<key>` and `read` on `<transit_mount>/keys/<key>`. Defaults to `BAO_TOKEN`, then `VAULT_TOKEN`.
- `transit_mount` (String) Mount path of the transit secrets engine. Defaults to `transit`.
